# Допущения и принятые решения

## 1. Определение переписки (Threading)
Для связи писем в переписку используется:
1. В первую очередь — заголовки In-Reply-To / References.
2. Если их нет — нормализованный subject + email контакта.
3. Иначе — создается новая переписка.

## 2. SLA и повторные ответы клиента
- SLA (slaDueAt) устанавливается при первом входящем письме без ответа менеджера.
- Если менеджер ответил, а клиент пишет снова — статус меняется на NEW или IN_PROGRESS, но slaDueAt может обновляться.
- Для MVP: если slaNotifiedAt не установлено и новое входящее — slaDueAt обновляется на now + sla_response_minutes.

## 3. Дедупликация писем
- Уникальность по messageId (глобальный ID письма).
- Если messageId отсутствует — deterministic hash от from + subject + date + body (первые 200 символов).

## 4. IMAP/SMTP безопасность
- Пароли почтовых ящиков шифруются AES-256-GCM.
- Ключ шифрования EMAIL_ENCRYPTION_KEY должен быть 32 байта в base64.
- В UI пароль никогда не возвращается.

## 5. Права доступа к шаблонам
- GLOBAL шаблоны видны всем.
- PERSONAL шаблоны доступны только создателю.
- Админ видит все шаблоны.

## 6. Авторизация
- JWT в HTTP-only cookie (sameSite=lax, httpOnly=true).
- secure=false для локальной разработки без HTTPS.
- При доступе по IP из локальной сети cookie должны работать корректно.

## 7. Cron и фоновые задачи
- Отдельный контейнер с простым циклом fetch.
- Не используется Redis/BullMQ на этапе MVP.
- CRON_SECRET в заголовке x-cron-secret.

## 8. Интерфейс
- Полностью на русском языке.
- Минимум лишних полей.
- Пустые состояния с понятными сообщениями.

## 9. Docker и сеть
- Приложение слушает 0.0.0.0 внутри контейнера.
- Порт пробрасывается наружу без привязки к 127.0.0.1.
- Доступ по локальному IP из сети.

## 10. Локальная разработка без Docker
- DATABASE_URL для локальной разработки: postgresql://crm:password@localhost:5432/crm
- Внутри Docker DATABASE_URL переопределяется на db:5432.
